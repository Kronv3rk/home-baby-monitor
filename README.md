# HomeBabyMonitor

Android-видеоняня для двух телефонов в одной Wi-Fi-сети. Один телефон передаёт изображение и звук, другой показывает трансляцию. Аккаунт и интернет не нужны.

**Версия 0.4.8 — экспериментальная.** Работа на реальных моделях телефонов, особенно с погашенным экраном, ещё не проверена. Приложение нельзя использовать как единственный способ наблюдения за ребёнком.

Версия 0.4.7 исправила инициализацию WebRTC JNI. В 0.4.8 добавлены полноэкранный монитор, локальный предпросмотр камеры, двусторонние настройки звука, новые звуки для сна и измерение реального битрейта на принимающем устройстве. Исправление требует проверки на реальном телефоне.

## Возможности

- Подключение по QR-коду или коду с экрана камеры. При необходимости можно указать IP вручную. Новый телефон не может вытеснить активного родителя с другого адреса.
- Видео и звук через WebRTC. **Качество задаётся на телефоне-камере**, есть 640 × 480/15, HD/30, Full HD/30 и /60, 2K/30 и /60; по умолчанию используется Full HD/30 с адаптацией под реальные режимы камеры. На мониторе видны разрешение, частота полученных кадров и измеренная скорость передачи; поток можно развернуть на весь экран, при необходимости обрезав края для заполнения дисплея. На камере есть локальный предпросмотр для кадрирования.
- Двусторонняя связь: отдельное включение микрофона камеры, постоянный микрофон или «нажми и говори» на мониторе, независимое отключение входящего звука и регулировка его громкости на каждом телефоне. При уходе приложения с экрана микрофон родителя отключается.
- Уведомления о длительном громком звуке, потере связи и прекращении поступления видеокадров.
- Звуки для сна: две колыбельные, шкатулка, тихие колокольчики, дождь, прибой, ветер, белый и мягкий шум, сердцебиение. Они синтезируются на телефоне камеры без скачивания записей. Управление доступно с обоих телефонов; громкость можно менять без перезапуска мелодии, есть таймер.
- Уровень заряда камеры, программное повышение яркости, управление фонариком, повторное подключение после обрыва.

**Важно:** отключение микрофона камеры отключает обнаружение громкого звука. Не ставьте оба телефона слишком близко при разговоре: возможна акустическая обратная связь. Новые режимы Full HD / 2K лишь задают ограничения и запросы к камере и кодировщику, но не гарантируют битрейт, разрешение и задержку на конкретном устройстве. Уведомление о громком звуке — не распознавание плача. Музыка на телефоне ребёнка тоже может вызвать такое уведомление. Программное повышение яркости не заменяет инфракрасную камеру. Заявленный режим 2K/60 не означает, что конкретные устройства смогут передавать и принимать 60 кадров/с.

## Подключение

1. Установите **один и тот же подписанный release APK** на оба телефона с Android 8.0 или новее.
2. Подключите телефоны к одной домашней Wi-Fi-сети. Интернет необязателен; гостевая сеть с изоляцией клиентов не подойдёт.
3. На телефоне в комнате ребёнка выберите **«Камера»** и разрешите съёмку и микрофон. Размещайте устройство и зарядный кабель вне досягаемости ребёнка.
4. На втором телефоне нажмите **«Сканировать QR-код»**. Можно также ввести код вручную.
5. Убедитесь, что видео и звук воспроизводятся. Отдельно проверьте громкость тревог, обрыв Wi-Fi и работу с выключенными экранами.

После успешного сопряжения код и QR на камере скрываются; их можно показать кнопкой. Камера не закрывает экран при временном отсутствии локального адреса: поиск Wi-Fi повторяется автоматически. Если обнаружение не срабатывает, используйте IP, указанный под QR-кодом.

## Отчёт об аварийном завершении

Если Android закрыл приложение, откройте его снова. Внизу экрана может появиться кнопка **«Отправить отчёт о последнем сбое»**. Она собирает сведения о предыдущем завершении процесса Android, а для нативных сбоев Android 12+ — сохранённый системой двоичный журнал, если он доступен. Отчёт помещается в ZIP и **не отправляется автоматически**: вы сами выбираете приложение для передачи. Перед отправкой помните, что системный журнал может содержать технические сведения об устройстве.

Для установления точной причины ошибки на конкретном телефоне нужны первые строки аварийного журнала (строка с `signal` или `FATAL EXCEPTION` и первые 15 кадров стека). Последние кадры со стандартным циклом Android ничего не говорят о причине.

## Установка обновлений

Release APK начиная с версии 0.4.2 подписываются **одним постоянным ключом**. Следующие версии с тем же сертификатом и увеличенным `versionCode` устанавливаются поверх предыдущей release-версии. При переходе с debug-сборки требуется удалить её один раз.

Обычный GitHub Actions создаёт **неподписанный** release APK — устанавливать его нельзя. Подписанный APK можно публиковать в GitHub Releases через workflow **Publish signed APK**, но для него необходимо один раз добавить два защищённых GitHub Secrets. До настройки секретов готовые подписанные APK остаются вне Releases. Ключ подписи не публикуйте в репозитории; подробности — в [SIGNING.md](SIGNING.md).

## Сборка и тесты

Нужны JDK 17, Android SDK 36 и Gradle 8.13. Команды из корня репозитория:

```bash
gradle :app:testDebugUnitTest :app:lintRelease :app:assembleRelease
bash tools/verify-jvm.sh
```

Вторая команда требует установленного Kotlin CLI. Неподписанный APK появится в `app/build/outputs/apk/release/`. Данные проверок — в [VALIDATION.md](VALIDATION.md); анализ рисков сопряжения — в [SECURITY_AUDIT.md](SECURITY_AUDIT.md).

## Структура

- `core/` — протокол, сопряжение, проверка адресов, сигналы о звуке.
- `net/` — обнаружение камеры, TCP-соединение, работа с Wi-Fi.
- `rtc/` — WebRTC, видеозахват, коррекция изображения.
- `audio/` — создание звуков для сна.
- `ui/` — интерфейс Jetpack Compose.
- `MonitorService.kt` — фоновая служба, оповещения и управление соединением.

Сигнализация шифруется AES-256-GCM, медиа передаются через WebRTC внутри локальной сети. Внешнего сервера, облачной записи, аккаунтов и аналитики в текущем исходном коде нет. Протокол сопряжения **не проходил независимый криптографический аудит**.
