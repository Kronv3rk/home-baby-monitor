# Домашняя няня — Android / локальная сеть

**Версия 0.3.2 — экспериментальный прототип. JVM-тесты, Android unit-тесты, Lint и сборка debug APK проходили в CI. Работа на двух реальных телефонах пока не подтверждена.**

Одно Android-приложение для двух устройств в домашней сети Wi-Fi: «Камера ребёнка» и «Родительский монитор». Видеопоток и звук идут **напрямую через WebRTC**; у PeerConnection пустой список ICE-серверов, собственный локальный TCP-канал передаёт предложение/ответ/ICE-кандидаты. Никаких аккаунтов, облачного хранилища и серверов сигнализации.

## Что реализовано в исходном коде

- Нативный Android: Kotlin, Jetpack Compose, WebRTC.
- Автопоиск камеры по UDP broadcast; резервное подключение по IP-адресу.
- Случайный 20-символьный код сопряжения (100 бит энтропии), вводимый вручную со второго телефона. Код **никогда не передаётся по сети**. Сигнализация (SDP/ICE) шифруется AES-256-GCM с разными ключами для двух направлений, уникальным вызовом сервера и защитой от повторного воспроизведения. Недоступен режим совместимости с открытым протоколом v0.2.
- Видео 640×480, до 20 кадров/с; микрофон и воспроизведение звука.
- Обратная связь «нажмите и говорите».
- Foreground service для камеры/микрофона и звука при погашенном экране, wake lock + Wi-Fi lock.
- Передача заряда телефона с камерой и статуса зарядки.
- Контроль долгого громкого звука, предупреждение родителя при потере heartbeat, отсутствии первоначального подключения или остановке видеокадров.
- Автоматическое повторное подключение к камере, TCP keepalive на уровне прикладного протокола (PING каждые 2 с; тайм-аут 14 с).
- Ночной режим: программная коррекция яркости, снижение частоты кадров. **Не инфракрасное ночное видение.**
- Команда фонарика: **может не работать**, если камера Android запрещает управлять вспышкой во время видеосъёмки. Приложение сообщает об отказе.
- Интерфейс на русском языке.

## Как получить APK

1. Установите Android Studio с Android SDK Platform 36 и JDK 17.
2. Откройте папку `HomeBabyMonitor` как проект Gradle. Подтвердите синхронизацию зависимостей из Google Maven и Maven Central.
3. Запустите задачу `:app:testDebugUnitTest`, затем `:app:assembleDebug`.
4. APK должен появиться в `app/build/outputs/apk/debug/app-debug.apk`.

В репозитории GitHub workflow `Android CI and APK preview` из `.github/workflows/android.yml` автоматически запускается при отправке кода в `main` и при открытии pull request. При успешной сборке APK загружается в **Actions → Artifacts**, а для `main` публикуется предварительный релиз **v0.3.2** в **Releases**.

**Android-сборка v0.3 прошла успешно** в GitHub Actions, включая `testDebugUnitTest`, `lintDebug` и `assembleDebug` (сборка № 42418891686 в исходном CI). Перенесённая версия 0.3.2 сохраняет исправленный код компиляции и будет проверена в собственном workflow. Это не означает проверки аппаратных функций на реальных устройствах. Не используйте приложение как единственный способ наблюдения за ребёнком.

**Внимание при обновлениях:** это debug APK, подписанный временным отладочным ключом GitHub runner. Две сборки из разных запусков могут быть несовместимы по подписи. При ошибке установки обновления сохраните настройки вручную, удалите предыдущую версию и установите новую. Для постоянных обновлений понадобится release signing key, хранящийся вне публичного репозитория.

## Начало работы

1. Установите один и тот же APK на оба Android-телефона (Android 8.0+, API 26+).
2. Подключите их к одному домашнему Wi-Fi, **не к гостевой сети с изоляцией клиентов**. Интернет может быть отключён.
3. На телефоне возле ребёнка нажмите **«Камера ребёнка»**, выдайте разрешения и запомните показанный код.
4. На втором выберите **«Родительский телефон»**, введите код. IP можно оставить пустым для автопоиска.
5. Дождитесь **«Связь установлена»**, убедитесь, что и видео, и аудио реально приходят.
6. Для ночного использования выключите оптимизацию батареи для приложения, подключите оба телефона к безопасным зарядным устройствам и проверьте работу с погашенными экранами.
7. Проверяйте надёжность связи опытным путём; приложение **не является сертифицированным детским монитором**, не заменяет непосредственный присмотр.

## Приватность и безопасность

- Видео, звук и команды управления шифруются WebRTC (DTLS-SRTP / data channel).
- **Сигнальный TCP-канал шифруется AES-256-GCM**, но это не TLS: ключ выводится из криптографически случайного 100-битного кода, который вводят на втором телефоне. Каждое TCP-соединение использует новый случайный вызов и два независимых ключа, сообщения нумеруются. Пассивное чтение сети и изменение сигнализации без знания кода не должны раскрывать аудио/видео; безопасность реализации требует независимого аудита. Не используйте публичный Wi-Fi.
- Нет отправки в облако, внешних ICE-серверов, регистрации или аналитики. Разрешение Android `INTERNET` необходимо также для обычных сокетов внутри Wi-Fi.
- Android 14+ разрешает запуск камеры/микрофона в foreground service, **если служба запущена из видимого приложения**. Если ОС/прошивка принудительно завершает процесс, автоматический запуск камеры в фоне не гарантирован.
- Android 16 в некоторых режимах требует `NEARBY_WIFI_DEVICES`; Android 17 требует `ACCESS_LOCAL_NETWORK` для приложений с target SDK 37+. Прототип собирается с target 36. При переходе на target 37 необходимо добавить новый runtime permission и его обработку. [Документация Android](https://developer.android.com/privacy-and-security/local-network-permission).

## Ограничения этого прототипа

- Срабатывание «возможный плач» — **энергетический порог продолжительного громкого звука**, а не обученная модель распознавания детского плача. Возможны пропуски и ложные тревоги.
- Автопоиск через широковещательные пакеты может блокироваться настройками роутера. Используйте IP камеры.
- Фонарик в некоторых камерах нельзя включить через `CameraManager.setTorchMode`, если эту же камеру уже использует видеозахват.
- Ночной режим только увеличивает яркость доступного сигнала; без освещения камера не увидит ребёнка.
- Не измерены фактическая задержка, расход батареи, температура, потери кадров и устойчивость работы на конкретных моделях.
- Не проверены некоторые варианты отключения экранов, входящих звонков, режимов экономии заряда и Android 17.
- Не реализованы резервная доставка оповещений по независимому каналу, постоянная привязка доверенного устройства и отличение плача от телевизора/разговора. Сессионное защищённое сопряжение требует ручного кода при новом запуске.

## Протокол и компоненты

```text
Телефон ребёнка                    Wi-Fi роутер                   Родительский телефон
    Камера + микрофон  ───── WebRTC DTLS-SRTP P2P ──────>   Видео + громкоговоритель
      Громкий звук    ───── WebRTC DataChannel ─────────>   Тревога
      Заряд / ping    ───── WebRTC DataChannel ─────────>   Статус / watchdog
      Динамик         <───── WebRTC Audio ───────────────   «Говорить»
      Фонарик/ночь    <───── WebRTC DataChannel ─────────   Управление
      TCP 43182       <─── AES-GCM: SDP / ICE ─────────   Защищённая сигнализация
      UDP broadcast   ───── порт 43183 ─────────────────>   Автопоиск
```

`core/` — протокол, детектор звука, heartbeat; `net/` — TCP/UDP; `rtc/` — WebRTC и ночной фильтр; `MonitorService` — работа при погашенном экране; `ui/` — интерфейс.

## Тесты, запущенные без Android SDK

```bash
bash tools/verify-jvm.sh
```

Скрипт запускает шесть JVM-тестовых программ, включая стресс-тест протокола и интеграционную проверку TCP-сервера с Android-заглушками. Для полного Android-проекта предусмотрены Gradle unit tests, Android Lint и debug APK build через GitHub Actions.

Android unit tests: `app/src/test/java/com/homebabymonitor/core/CoreTest.kt`.

CI автоматически делает `:app:testDebugUnitTest :app:lintDebug :app:assembleDebug`. Отдельные инструменты `tools/verify-jvm.sh` запускаются локально при наличии `kotlinc`; в CI они не подменяют Android-тесты.
