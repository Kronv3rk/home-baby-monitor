# Проверка HomeBabyMonitor 0.3.1 (8 ноября 2026)

## Проверено автономно

- Логика локального адреса, громкого звука и watchdog видеокадров.
- Обмен TCP-сообщениями, ограничение размера и строгая UTF-8 в SDP/ICE.
- Шифрование сигнализации AES-256-GCM с уникальными 128-битными случайными значениями обеих сторон, независимыми ключами по направлениям и проверкой MAC.
- Запрет старого открытого протокола, ошибки неверного кода сопряжения, поддельных и повторных сообщений.
- Интеграционный обмен реального TCP-сервера и клиента с корректным и неправильным кодом.
- 2500 случайных SDP/ICE-сообщений и 500 последовательных TCP-передач.

Шесть наборов тестов выполняются командой `bash tools/verify-jvm.sh` на JVM Kotlin. Все шесть проходят (CoreSmokeTest, LocalSocketSmokeTest, SessionWatchdogSmokeTest, ProtocolStressTest, SecureChannelSmokeTest, ServerIntegrationSmokeTest).

## Проверка Android

- Сборка проекта с Android Gradle Plugin 8.13.2 и Kotlin 2.3.10 запускается через GitHub Actions. Исходная настройка `kotlinOptions.jvmTarget` выявлена как несовместимая с Kotlin 2.3; заменена на `compilerOptions`. Также устранена ошибка nullability в `NightFrameProcessor`, обнаруженная компилятором WebRTC.
- Успешная сборка v0.3 подтверждена GitHub Actions run 42418891686 (`:app:testDebugUnitTest`, `:app:lintDebug`, `:app:assembleDebug`); APK получен из артефакта. В отдельном репозитории v0.3.1 требуется собственная повторная проверка. Автономные тесты не доказывают отсутствие ошибок Android/WebRTC API.
- Физические устройства, отключённый экран, реальные задержки, устойчивость ночью, перегрев и автономность пока не тестировались.

## Оставшиеся риски

1. Никакой программный watchdog не заменяет надёжный сертифицированный детский монитор или непосредственный присмотр.
2. Обнаружение «плача» на практике означает длительный громкий звук, возможны ложные тревоги и пропуски.
3. Производители Android могут ограничивать камеру/микрофон с погашенным экраном или завершать фоновые процессы.
4. Ночной режим программный, при отсутствии света камера не получает деталей; фонарик может быть заблокирован драйвером камеры во время видеозахвата.
5. Шифрованное сопряжение использует собственный протокол поверх стандартного AES-GCM; независимый криптоаудит ещё не выполнялся. Доверие к физически показанному коду обязательно.
6. Нет независимого второго канала аварийных оповещений и контроля фактического аудиовывода на динамик.
